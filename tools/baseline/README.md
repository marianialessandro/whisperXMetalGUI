# Baseline and experimental Metal CTC

These tools run directly from the command line. They do not launch or test the macOS UI. Experimental CTC candidates do not change the production WhisperX backend and do not constitute the full quality/GPU certification gate.

An optional `components` object in the pinned community-1 model specification maps `speaker_segmentation`, `speaker_embedding` and `speaker_plda` to their declared checkpoint files. Inspection verifies every file hash and the corresponding `$model/segmentation`, `$model/embedding` and `$model/plda` references in the hash-verified `config.yaml`. PLDA requires both `plda/plda.npz` and `plda/xvec_transform.npz`. Verified roles are recorded once for the shared snapshot; unverified or mismatched component declarations do not satisfy the full runner's role requirements. The legacy single `role` field remains supported. Manifest collection now uses the declared Torch Hub transport for Torch checkpoints, instead of looking for Hugging Face snapshots, and preserves verified component roles without claiming loadability.

`diagnostic_pair.py` optionally accepts `--voices --diarization-specs INVENTORY --torch-specs INVENTORY --bridge PRIVATE_PIPE`, with optional `--speaker-count N`. It checks licensed audio, ASR and alignment identities, all three community-1 components, shared HF cache and pinned local default references before reading the private credential. The original worker and adapter then run in separate offline cold processes with the existing algorithm and optional seed. A successful voice diagnostic requires equivalent JSON/TXT/SRT/VTT, no worker warnings, completed diarization and speaker-assignment calls, and speaker labels in the result. Python networking is denied; this is not OS network isolation. Credentials remain in memory and private stdin; output and evidence do not contain them. Defaults remain voices off and automatic speaker estimation when enabled without a count. These paired diagnostics remain separate from independent natural accuracy, operator trace review, calibration and the full gate.

The runner creates an owned process group before each worker starts. Timeout or caller interruption terminates that group, including descendants whose parent has already exited, and closes private input/output pipes. A graceful stop is followed by a forced stop of remaining group members. Real parent/grandchild regressions exercise both termination paths and the exited-leader case; these process controls do not count as natural quality or complete worker coverage across all pipeline stages.

The full runner routes verified inventories by transport: one Hugging Face cache becomes `HF_HUB_CACHE`, and one Torch Hub cache becomes `TORCH_HOME` for both original and adapter children. Inventory order does not select the cache. Multiple roots within either transport or an unsupported transport fail preflight; different Hugging Face and Torch roots are supported. Checkpoint identity, worker-default identity, licenses and corpus prerequisites still apply independently.

`provision.py --specs INVENTORY --bind-default-ref preflight` optionally creates a missing Hugging Face `refs/main` at the explicitly declared snapshot revision, after verifying every declared file hash and the recorded license. This offline cache metadata operation uses an exclusive atomic link, preserves conflicting existing references and concurrent writers, and removes its own temporary file. Existing matching references are unchanged; Torch Hub has no such reference. Without this flag, preflight remains read-only. This binds the local baseline cache to its chosen snapshot; it does not assert that the remote main branch currently points there.

`alignment_inventory.py --source-root ROOT --model-specs INVENTORY [--out NEW_JSON]` inventories the selected source's literal Torch alignment defaults against the running torchaudio package, without importing the WhisperX source or loading checkpoints. It verifies bundle names, checkpoint filename/URL, runtime version, configuration and ordered labels; records sample rate, waveform normalization, removed auxiliary axes and source digests; and rejects mismatches. Run it with the selected bundled Python. It denies Python networking during inspection and refuses output overwrite. The full runner performs this inspection in the explicitly selected runtime and rechecks source identity before accepting Torch default-selection evidence, alongside checkpoint hashes. Hugging Face revisions retain their separate refs check. This is selection/config evidence, separate from actual loadability, inference, quality and full-gate certification.

## Build the native tools on Apple silicon

Use the installed Xcode command-line compiler and system Foundation/Metal frameworks. Generated binaries belong under the ignored `macOS/output/` directory.

```sh
mkdir -p macOS/output/baseline/tools
xcrun clang++ -std=c++20 -O2 -fobjc-arc -Wall -Wextra -Wno-unused-function -Wno-deprecated-declarations tools/baseline/native_ctc_probe.mm -framework Foundation -framework Metal -o macOS/output/baseline/tools/native_ctc_probe
xcrun clang++ -std=c++20 -O2 -fobjc-arc -dynamiclib -Wall -Wextra -Wno-unused-function -Wno-deprecated-declarations tools/baseline/native_ctc_bridge.mm -framework Foundation -framework Metal -o macOS/output/baseline/tools/libnative_ctc.dylib
shasum -a 256 macOS/output/baseline/tools/libnative_ctc.dylib
```

`native_ctc_probe --help` describes the standalone NPZ-based primitive diagnostic, including optional `--compact` and `--batched` modes. Its defaults and existing arguments remain supported.

`native_npz_inventory --model FILE --sha256 HASH [--output NEW_JSON] [--payload-hashes]` optionally streams each raw tensor payload through SHA256 in blocks bounded to one MiB. Shape, dtype, byte order and Fortran storage metadata remain unchanged; default output has no payload fingerprints. The expected whole-file hash is verified before payload inspection or output creation. This checks byte-level reading and can be compared with independent NumPy payload fingerprints, including empty/scalar tensors, nonnative byte order, signed zero and NaN payloads. It does not allocate complete tensors, decode numerical values, convert a model or execute a network.

Build the updated inventory tool with `xcrun clang++ -std=c++20 -O2 -Wno-deprecated-declarations tools/baseline/native_npz_inventory.cpp -o NEW_BINARY`, then use that binary's path for the inventory command.

## Run alignment trials

```sh
macOS/output/installer/WhisperX.app/Contents/Runtime/bin/python3 -I -B tools/baseline/ctc_alignment_trial.py --help
```

Supply an existing licensed audio asset and its expected SHA256, original ASR JSON and its expected SHA256, the verified private torchaudio model specification, language, and a new output directory. The ASR JSON is an oracle input, not independent word/speaker ground truth. The script refuses overwrite and missing checkpoint/license prerequisites.

The default `--ctc-backend mlx` preserves the first experimental trial. `--ctc-backend native` uses the standalone binary and private temporary NPZ files per segment; it requires `--native-binary` and `--native-binary-sha256`. Startup and compilation remain part of that candidate's timings.

`--ctc-backend native-persistent` requires `--native-library` and `--native-library-sha256`. It creates one native context for all segments and replicas, compiling the shaders once and reusing growable Metal buffers. Input and final path cross a synchronous in-memory C ABI. Native setup time is reported separately; input copies, completion and final path materialization remain part of the candidate alignment timing. Optional `--warmup --replicas 6` runs warm alternating original/candidate replicas. Run timing trials separately from GPU tests or other benchmark jobs.

Optional `--native-wildcard-max` requires the persistent backend and the `wxctc_row_max` ABI extension. A scoped Torch dispatch mode redirects CPU FP32 `max(dim=1)` without gradients/keepdim to the native Metal row reduction. Other operators follow their original implementations. The kernel returns exact maximum values and first indices on ties, supports nonpositive log scores including negative infinity, and rejects NaN/positive values. The additional pipeline is created lazily on first use and cached; warmup includes its setup. No production source or default is changed.

The original blank mask/gather and concatenation remain on CPU. Reduced values and int64 indices return to CPU before the original code constructs the CTC emission matrix. This extra readback and the dispatch-mode overhead are included in candidate alignment timings. The report records `wildcard_spans` and the actual dispatch count, which can be zero when no wildcard is needed. It does not certify a speedup caused by moving this reduction alone.

Alternatively, `--native-fused-wildcard` uses the persistent backend and the `wxctc_compute_wildcard` ABI extension; it cannot be combined with `--native-wildcard-max`. Trial-only wrapper tensors defer the original masked selection, maximum and concatenation without allocating or returning placeholder numerical values. The CTC boundary receives the original unextended FP32 emission and tokens; token index equal to the source vocabulary selects the virtual wildcard. Metal validates input, excludes the blank from the row maximum, extends the emission on GPU, and runs prefix/trellis/backtracking in the same second command buffer. There is no intermediate wildcard readback or host gather/concatenation of the score matrix. Two command-buffer completions remain per CTC call, plus the final path readback.

The deferred adapter supports the exact preparation operations used by the current alignment oracle on the pinned Torch runtime. It checks mask, vocabulary, blank and source identity; requests to materialize deferred values or use unsupported operations fail explicitly. It is a feasibility adapter, not a general tensor implementation or production backend. Mask/token metadata, original MPS-to-CPU emission and the copy to native shared buffers still use CPU. The report counts actual fused dispatches in `native_fused_wildcard_dispatch_count` and records logical intermediate readback bytes and retained buffer capacity. GPU extension needs an additional retained emission buffer, so fewer transfers do not imply lower total memory use.

Optional `--native-character-segments` requires the persistent backend and pinned CPython 3.12 float-sum semantics. After GPU backtracking, `ctc_merge_repeats` computes frame bounds and the mean score per token in the same command buffer. Binary64 addition/subtraction/division and the CPython 3.12 Neumaier correction are emulated with 64-bit integer operations for this bounded nonnegative FP32 probability domain. This preserves the sum policy without switching character means to FP32. It is not a general IEEE floating-point library.

The `wxctc_compute_segments` ABI extension returns 16-byte character segments plus path-length control, without reading back all frame points. Scoped trial hooks use those segments with the original transcript labels. GPU grouping/means do not change the original CPU timestamp scaling, word/sentence reductions, missing values or interpolation. `--return-char-alignments` optionally includes the original detailed character JSON in both outputs and their exact comparison. Both new flags default to false. Output payload can be larger than a path when token/frame counts are similar; the report exposes actual logical sizes and does not claim total memory/driver transfer measurements.

Results contain exact aligned JSON comparison, source input identities, native library/shader identity, setup time, command completion times and explicit CPU residuals. Buffer lengths describe retained Metal shared-buffer capacity; they do not measure total physical process/GPU memory. Neural inference follows the original alignment implementation; the optional flags select which character, timestamp, word mean and wildcard stages use native Metal. Unselected reductions use the original implementation. MPS-to-CPU and CPU-to-native copies remain; this is not a zero-copy pipeline.

## Experimental word/sentence timestamp bounds

Add `--native-timestamp-bounds` to a `native-persistent` alignment trial to run timestamp minima/maxima on Metal. It can be combined with fused wildcard and character segments. A temporary proxy replaces only the alignment module's Pandas reference; character-frame subsets retain a scoped Series subclass whose `start`/`end` min/max call the native context. Other Pandas users, means, labels, selection, timestamp scaling, rounding, interpolation and final sentence grouping keep the original behavior. The proxy restores even after an error.

The optional `wxctc_timestamp_bounds` ABI extension compares binary64 bit patterns using ordered integer keys, without FP32 conversion or double arithmetic. One 256-lane GPU group skips NaNs and emits both extrema plus a validation word. Empty/all-missing inputs return NaN; finite signed values and infinities are supported. Negative zero is rejected explicitly because NumPy's zero tie behavior can depend on its reduction path. Unsupported reducer options/dtypes or inputs over 32768 values fail without a numerical CPU fallback. Object columns containing only `None` are converted to float64 NaNs before transport.

The report includes dispatch counts, per-call completion/GPU times, reference Pandas/NumPy versions and copies: eight input bytes per value and 24 logical output bytes, excluding ABI metadata and driver copies. This feasibility adapter performs a separate synchronous dispatch for each reduction. Small word subsets may cost more in CPU/GPU synchronization than their arithmetic; timing must be checked before promotion. Batching and keeping character timestamps resident are subsequent work. No production default changes or full quality certification follow from these trials.

## Batched timestamp bounds

Use `--native-timestamp-bounds-batched` instead of `--native-timestamp-bounds` with the persistent backend to group extrema for all words/sentences of each character frame. It preserves the existing flags/defaults and is mutually exclusive with the individual timestamp mode. The scoped NLTK loader proxy records the spans emitted by the original tokenizer, then the Pandas factory builds the exact inclusive sentence selections and non-space word selections used by the oracle. Labels, spaces and word IDs are CPU metadata; no sentence splitting is reimplemented.

The `wxctc_timestamp_bounds_batch` ABI v1 extension receives one binary64 timestamp array and CSR query indices/offsets. Metal validates offsets and indices before reading selected values, then runs one 256-lane group per subset in one command buffer. Limits are 65536 input values, 32768 queries and 4194304 index entries. Empty subsets and NaNs follow the individual mode; selected negative zero fails explicitly. Validation failure leaves caller output untouched. Existing ABI exports/layouts are unchanged.

Each character frame uploads its start/end columns once for the batch. The scoped Series retrieves the requested extrema from the completed GPU results, checking subset identity and timestamp snapshot bytes; mutation or an unregistered subset fails instead of using stale data or falling back to CPU min/max. The Pandas/NLTK references restore on exit and error. This adapter belongs to a standalone CLI process and does not support concurrent original alignment calls while its hooks are installed.

Reports retain `native_timestamp_bounds_dispatch_count` for actual batch dispatches and add query/consumption counts. Logical transfer includes timestamp bytes plus CSR metadata; readback is 16 bytes per unique subset plus a four-byte validation word, excluding ABI metadata and physical copies. This does not eliminate character readback, CPU scaling/rounding, snapshot checks or the upload from CPU; retaining timestamps across the complete character/word pipeline remains subsequent work. Word means remain original unless `--native-word-means` is selected; interpolation and production defaults remain original.

## Optional Pandas constructor optimization

Add `--native-timestamp-fast-frames` with `--native-timestamp-bounds-batched` to avoid Pandas subclass reconstruction through temporary base Series/DataFrame objects. The adapter constructs its scoped subclasses directly from the managers already supplied by Pandas, then leaves column names, metadata finalization and copy-on-write behavior to the original caller. The option supports the inspected Pandas 3.0.6 runtime only; a different version fails explicitly before installing hooks because these manager methods are private APIs. The existing batched path remains available without the option.

This reduces CPU adapter overhead for the existing Metal kernels; it does not move another numerical operator to GPU, change transfers, remove snapshot validation or keep timestamps resident between pipeline stages. Reports record the flag globally and on each batch. Regression tests cover numeric/string dtypes, column names, selection and projection, missing values, original means, cache invalidation, parent isolation after modifying a derived frame, hook restoration and the runtime guard. All runs remain direct CLI processes without UI.

## Experimental word score means on Metal

Add `--native-word-means` to the batched timestamp trial, optionally with the fast frame constructors. It moves the selected non-space word score means to `ctc_word_means_batch`, through the additive ABI v1 export `wxctc_word_means_batch`. Each character frame uploads its rounded scores and CSR word selections once and completes one additional command buffer for all its means. Timestamp and score batches are currently separate; the previous modes/defaults remain available.

The pinned reference is Pandas 3.0.6 with NumPy 2.2.6 and `np.getbufsize() == 8192`; unsupported settings fail before installing the mean adapter. Pandas replaces NaNs with positive zero for the sum and excludes them from the count. Metal retains their positions and reproduces the [NumPy pairwise order](https://github.com/numpy/numpy/blob/v2.2.6/numpy/_core/src/umath/loops_utils.h.src): eight accumulators, balanced leaf combination, tail additions and recursive splits at multiples of eight for blocks above 128. A bounded explicit stack implements the split tree. The outer sum combines 8192-element blocks in order, matching the pinned reduction buffering verified against the actual runtime. Binary64 addition and division use integer emulation already present in the character prototype; no FP32 narrowing or CPU numerical sum/mean is performed.

Supported score values are positive zero, finite values in 0.001..1 and NaN, matching the rounded character probability domain. Selected negative zero, negative values, infinities and other magnitudes are rejected. Limits: 32768 source scores and elements per word query, 32768 queries, 4194304 CSR indices. GPU validation checks metadata and score domain before summing; ABI output is untouched on failure. Empty/all-missing queries yield NaN. The scoped score Series returns a NumPy float64 scalar from the completed GPU batch so original `round(..., 3)` semantics are preserved. Unsupported subsets/options/dtypes and changed snapshots fail without a CPU mean fallback.

Reports separate `word_mean_spans`, real mean dispatch count and consumed word requests from timestamp counts. Per mean batch, logical readback is eight bytes per unique word plus four validation bytes; input includes scores and CSR metadata. CPU character scaling/rounding, final mean rounding, labels, selection, snapshots, interpolation, character readback and uploads remain. This is another numerical GPU feasibility step, not production promotion, a zero-copy claim or independent quality certification.

## Fused timestamp and word reductions

Add `--native-fused-reductions` with `--native-word-means` to use one interleaved binary64 `(start, end, score)` input, one shared CSR row query set and one Metal kernel per character frame. Modes bits 1/2/4 request minimum start, maximum end and mean score. A word's row indices serve all three operations; sentence selections still follow the original inclusive spans and literal-space exclusion. Previous separate-batch modes and defaults remain available.

The additive `wxctc_alignment_stats_batch` ABI v1 export validates row counts, lengths, capacities, mode bits, CSR metadata and selected numerical domains. Unrequested output fields are NaN and the scoped adapter rejects requests for operations it did not register. The binary64 extrema and NumPy score-sum policies are unchanged; the score helper reads interleaved data at stride three without altering its order. Limits: 32768 rows/queries/elements per subset and 4194304 CSR indices. Outputs are caller-owned triples, copied only after successful GPU completion/validation.

The fused core writes directly from its Metal shared output buffer into the caller's output memory while holding the context lock. It creates no intermediate C++ result vector for this export. The record exposes zero native host result staging bytes and one native result memcpy; this does not mean zero physical copies, zero Python snapshot allocations or zero-copy GPU transport. Previously exported functions preserve their behavior.

`timestamp_bounds_spans` carries the fused group's actual input/readback bytes, completion time and one command buffer. `word_mean_spans` is an explicitly marked component of that same completion group: `separate_dispatch=false`, zero additional command buffers and zero additional transfer bytes. Its GPU interval is shared, not a second independently measured kernel interval; do not sum duplicated component times. `native_word_means_dispatch_count` excludes these components; completed mean group/consumed request counts remain available. The report separately counts fused groups and unique row subsets.

Add `--native-compact-reduction-plan` to optionally use clipped integer sentence ranges, shared word row tuples and one row gather per fused subset for snapshot construction. Original snapshot bytes and mutation checks are preserved. A whole row gather can copy unused columns on CPU; the report distinguishes requested snapshot bytes from temporary gathered bytes and counts gather calls. This changes host preparation only, not numerical GPU placement or GPU transfer sizes. Plan/cache wall times are partial local intervals, not a partition of complete alignment time. Compare complete alignment timing before drawing performance conclusions.

All extensions remain standalone CLI feasibility work. Character readback, CPU timestamp scaling/rounding, final score rounding, interpolation, metadata, snapshots and uploads remain. The production backend and full quality gate are separate pending work.

## Optional exact character rounding

Add `--native-character-rounding` with `--native-character-segments` to round character start/end timestamps and character scores on Metal. A scoped metadata-only coordinate adapter receives the original ratio/offset, performs the original Python float scaling operations in a batch, then calls the additive `wxctc_round3` ABI v1 export once for that character segment. Only completed numerical GPU results are returned to `round(..., 3)`; unsupported digits, types, materialization order or changed scale fail explicitly. The adapter supplies no placeholder numerical values.

The kernel implements fixed CPython `round(value, 3)` semantics, not NumPy's scalar rounding. It multiplies the exact integer significand by 1000, applies a nearest-even integer quotient, then converts the decimal rational back to binary64 with the existing integer division emulation. Tiny values preserve the sign of zero; values with binary exponent at least 43 already have spacing larger than twice the rounding error bound and remain unchanged. Nonfinite values preserve their bit payloads. No FP32 narrowing or host numerical rounding is performed. The reference [CPython 3.12.12 implementation](https://github.com/python/cpython/blob/v3.12.12/Objects/floatobject.c) uses correctly rounded decimal conversion; the optional Python bridge pins that runtime. This is fixed three-decimal rounding, not a general precision arithmetic library.

The primitive accepts 1..98304 binary64 values and copies results directly into caller-owned memory after a completed GPU command, without a native result vector. Reports expose character round groups and their input/readback bytes separately. It adds one command buffer and an upload/readback of scaled character triples per CTC segment. Character scaling, original character readback, final word-score NumPy rounding, interpolation and metadata stay on CPU. This option increases numerical GPU coverage; measurements must include its extra bridge/adapter cost, and it does not imply reduced total synchronization or resident timestamps. The fused reductions and rounding options can be selected independently within their stated prerequisites.

## Optional resident character scaling and rounding

Add `--native-resident-character-rounding` with `--native-character-rounding` to retain the raw character frame bounds and means in the native context. The additive ABI v1 `wxctc_prepare_segments` returns a metadata-only generation/count handle; it does not read the numerical character segments into Python. The next core CTC compute attempt invalidates that generation, including failed GPU validation. `wxctc_scale_round_segments` validates the generation/count under the context lock before using retained buffers. Other reductions can reuse their own temporary buffers without overwriting those segments; returned results remain caller-owned.

The scaling kernel multiplies each integer frame by the binary64 ratio using a two-limb integer product with nearest-even rounding, then separately adds the binary64 offset with guard/round/sticky bits. It then applies the exact three-decimal rounding kernel to timestamps and retained scores. Multiplication and addition remain separate operations, preserving the original Python expression; no FP32 narrowing, FMA or CPU character scaling is used. The original ratio calculation remains CPU. Supported frame counts are 1..32768, ratio is `[2**-23, 2**11)` and offset is zero or `[2**-23, 2**41)`; negative zero, negatives, subnormals, nonfinite parameters and values outside this bounded domain fail explicitly. Integer offsets must be exactly convertible within `2**53`; the native domain is narrower. Unsupported inputs do not fall back to CPU.

The final scale/round command uploads only 16 bytes of ratio/offset, reads `24*characters` numerical bytes and a four-byte validation flag, and performs one direct memcpy into caller-owned output. The prepare call retains a path-length control read and returns eight bytes of generation metadata. Raw `16*characters` segment readback and later `24*characters` scaled-input reupload are removed. The two CTC command buffers and the separate scale/round completion remain: ratio/offset arrive through the scoped alignment adapter after CTC. This is bounded character residency across those stages, not full pipeline residency, zero synchronization or a physical-copy/RAM claim. Final character DataFrame construction and its later fused-stat uploads remain CPU work.

## Optional resident fused statistics

Add `--native-resident-reductions` with `--native-fused-reductions` and `--native-resident-character-rounding` to reuse the final rounded character triples on Metal. Scaling now writes a dedicated retained buffer, including a GPU-generated all-NaN sentinel row. The additive ABI v1 `wxctc_alignment_stats_resident` uses the existing fused kernel and a single command buffer; no expansion kernel or new completion is added. Generation, character count and exact ratio/offset bits must match the latest successful retained scaling. New CTC computation or a failed native scale attempt invalidates retained numerical provenance.

Before dispatch, the Python wrapper verifies that all nonmissing character triples in the original DataFrame match an immutable byte snapshot of the completed scale/round output, in their original order. Only entirely NaN triples are treated as missing; partial NaN triples, modified values, missing/extra numerical rows, stale scale/generation and invalid indices fail explicitly. Query indices are remapped to retained character positions or the sentinel. NaN entries, duplicates and ordering are preserved in each CSR query, maintaining the pinned NumPy pairwise summation policy. Existing per-subset DataFrame mutation checks remain active.

Only remapped CSR indices, offsets and modes are uploaded; character-value upload is zero and query outputs/readback are unchanged. One final character readback remains for the original DataFrame. The host keeps `24*characters` bytes of immutable provenance, gathers the same numerical bytes for verification, creates a `4*rows` mapping, and remaps query indices. Records expose those host costs and the preparation interval separately; this is reduced logical transport, not reduced physical RAM or complete GPU residency. The default copied-input fused mode remains available for comparison and all existing ABI layouts/exports remain unchanged.

## Optional word-score rounding in the resident statistics group

Add `--native-word-rounding` with `--native-resident-reductions` to complete the final three-decimal word-score rounding on Metal. The additive ABI v1 `wxctc_alignment_stats_resident_rounded` returns the original query triples followed by one rounded score per query; capacity covers four uint64 elements per query. A second tracked encoder runs `ctc_round_word_means` in the same command buffer after the statistics kernel. Validation completes before either result array is copied into caller-owned output. Existing three-element exports/layouts remain unchanged.

The bounded score helper reproduces [NumPy 2.2 rounding](https://numpy.org/doc/2.2/reference/generated/numpy.round.html): binary64 multiplication by 1000, nearest-even integer rounding and binary64 division by 1000, each rounded separately. This differs from CPython decimal rounding at some boundaries, so the character helper is not reused. Only means from the validated nonnegative score domain reach the helper, with NaN for absent queries; arbitrary values and precisions are not supported. Tests expose the exact GPU helper through a test-only shader variant and compare scalar NumPy rounding for random probabilities and neighbors around all 1000 half-thousandth boundaries.

`NativeRoundedWordMean` is an actual np.float64 mean subclass whose numerical value remains the unrounded completed GPU mean. Its `__round__(3)` returns a completed np.float64 GPU rounding result; unsupported digits fail explicitly. The original alignment call uses this method unchanged, preserving its scalar rounding type. No placeholder mean or CPU numerical rounding is used for those calls. Each query adds eight readback bytes and the native bridge copies the two completed result arrays directly; no extra completion, character upload or native result vector is introduced. Queries without a mean produce NaN in the extra slot. CPU metadata, provenance snapshots, final character readback, ratio calculation and interpolation remain.

## Optional default nearest interpolation

Add `--native-nearest-interpolation` with `--ctc-backend native-persistent` to replace the scoped alignment `interpolate_nans` helper for default nearest timestamp filling. This option is independent of the resident-character flags. The additive ABI v1 `wxctc_interpolate_nearest` accepts 1..32768 binary64 values. One sequential GPU scan computes previous/next valid indices in linear work, then a tracked second encoder selects the nearest value and fills the ends, in one command buffer. Only integer distances and binary64 bit copies are used; equal distances choose the previous value, matching [SciPy 1.15.3 nearest policy](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.interpolate.interp1d.html). Existing values, signed zero and infinities retain their bits. All-missing input replicates the first NaN payload, matching the pinned Pandas forward/back-fill behavior.

The Series adapter pins Pandas 3.0.6/SciPy 1.15.3, requires a contiguous zero-based index and float64 numerical dtype, and preserves the original index/name/attrs. Empty Series and object Series containing only None are metadata-only copies, reported without GPU dispatch; `ignore` remains an identity operation. Other interpolation methods, indices, nullable/nonnumerical dtypes and lengths outside the bound fail explicitly without a numerical CPU fallback. The production helper and all defaults remain original. Per numerical Series this adds one GPU completion, an eight-byte-per-element upload/readback and an eight-byte-per-element native neighbor buffer; direct caller-owned readback uses no native result vector. Reports distinguish completed numerical interpolation from metadata-only calls. Porting this default policy does not certify other methods or demonstrate a speedup.

## Optional paired subsegment interpolation and gap counters

Add `--native-interpolation-batched` with `--native-nearest-interpolation` to compute subsegment start/end columns together. A scoped factory recognizes the original subsegment rows, constructs an InterpolationFrame with the original unfilled values, computes the pair, then registers immutable input fingerprints and completed outputs. Each original `interpolate_nans` call validates its full column/index snapshot before returning an independent Series with the cached numerical result. No placeholder values are exposed and no numerical result is returned before GPU completion. Mutation or an unregistered column/index fails explicitly. Character-frame construction delegates to the existing resident-reduction proxy; that scope must be installed before paired interpolation. Both hooks restore on exit/errors.

The additive ABI v1 `wxctc_interpolate_nearest_batch` accepts one or two column-major inputs with up to 32768 rows per column. The GPU scans each column independently, including the all-missing first-payload policy, and returns `(input_missing, filled_missing)` counters per column. A missing value counts as filled only when the same column has a valid neighbor; all-missing columns report zero filled gaps. Old exports/layouts remain unchanged. The Python single-Series path also uses the new counter export. This distinguishes a completed interpolation routine from real gap filling. Control readback is eight bytes per column, in addition to the unchanged eight-byte-per-element numerical upload/readback.

Each supported subsegment pair uses one completion instead of two. Word-level Series retain standalone interpolation; object/all-None subsegment columns keep the metadata-only path. The paired frame retains the original DataFrame dtype/metadata and caches `16*rows` input fingerprint bytes plus the completed output until its original calls consume them. Returning an independent Series adds a host copy of that column, and preparation packs the two columns on CPU. Records expose `columns_consumed`; duplicated consumers do not represent another GPU command. This is scoped feasibility work, not full-pipeline residency or a default production change.

## Lifecycle and verification

### Direct MPS storage diagnostic

`mps_storage_probe.py` provides separate `build`, `probe` and `live` CLI commands. It is a Torch 2.8.0 development extension, outside the production worker and CTC bridge. Build a new local dylib with:


`probe` takes a hash-verified bounded CTC NPZ fixture, uploads its saved emission to MPS and compares GPU row maxima and first indices against a separate CPU oracle. This checks captured neural values, not live inference. `live` takes `--audio`, `--audio-sha256`, `--torch-specs`, `--language it|en`, `--library`, `--library-sha256` and a new `--out` JSON file. Optional `--start`, `--duration` and `--replicas` default to 0 seconds, 6 seconds and six runs. Duration is bounded to .5..30 seconds. Checkpoint hash/license verification precedes model loading; the existing Python network guard and offline cache environment apply during decode/inference and restore on exit. This guard is not OS network isolation. Audio hash validation identifies the existing corpus asset; its license and corpus provenance remain the caller's corpus prerequisites.

The live command produces torchaudio logits and log-softmax on MPS and passes the detached emission directly to the native operation before calling `.cpu()` for the separate reference. Native storage access follows the pinned [PyTorch MPS storage implementation](https://github.com/pytorch/pytorch/blob/v2.8.0/aten/src/ATen/native/mps/OperationUtils.h); it binds the original MTLBuffer with `storage_offset * element_size`. Only contiguous two-dimensional FP32 tensors without gradients or lazy negative/conjugate bits are supported, with 1..32768 rows, 1..4096 columns and at most 16777216 elements. NaN/positive log scores fail through a GPU validation flag; negative infinity is valid. Equal maxima keep the first index, including signed zero.

An owning Tensor and a strong MTLBuffer reference retain the allocation until completion. Calls serialize. The extension commits and waits for the current MPS stream under its serial dispatch queue, then submits and waits for one command buffer on a private Metal queue using the same device. Callers must not mutate aliased input storage concurrently. There is no fence-only or asynchronous handoff, and producer wait time is included in reporting. The tracked kernel reads the original emission buffer, with no candidate emission host readback or reupload. It reads back only `8*rows+4` bytes of completed maxima, uint32 indices and validation; physical traffic is unmeasured. CPU tensor allocation and bit-copying of final output remain. Pipeline setup is reported on first use.

The row-maximum commands prove bounded buffer access and a real numerical dispatch. Complete GPU placement, zero synchronization, end-to-end speedup and quality certification require separate evidence. Saved-fixture uploads and CPU reference readbacks are explicitly outside the candidate transport counters.

### Optional direct MPS emission input to native CTC

The alignment trial accepts additive `--ctc-backend native-mps`, `--mps-library` and `--mps-library-sha256` options. Build the Torch extension using the current `mps_storage_probe.py build` command; older row-maximum-only dylibs lack the `torch.classes.whisperx_mps_probe.CTC` extension. Existing trial backends and defaults keep their original behavior. Native-persistent reduction/residency flags require that original backend and cannot be mixed with native-mps in this first slice.

The scoped handoff tracks FP32 `log_softmax` for a batch of one and its original first-row selection. Both pinned Torch eager dispatch and inference-mode forms are supported. It replaces only that emission's default synchronous CPU conversion with a metadata-only wrapper retaining the actual MPS tensor. Detach, full-row slice and the original single-blank mask, maximum, unsqueeze and concatenation operations preserve metadata until native CTC consumes it. Numerical materialization through the wrapper, unsupported casts/copy options, missing handoff or changed blank metadata fail explicitly. Unrelated operations retain their implementation. Hooks restore on exceptions and scope exit.

`MPSCTC` owns a synchronous Torch custom-class context with reusable native pipelines/buffers. An owning input Tensor and strong MTLBuffer reference keep the borrowed storage alive through the MPS producer wait and both native CTC completions. Close serializes with compute, is idempotent, and invalidates future calls; the underlying custom class also rejects stale calls. Borrowed input is never retained in the CTC context. Callers must not mutate aliased storage concurrently. Shader and dylib hashes are checked before use. Dimensions, CPU int32 token metadata, gradient/layout/lazy-view constraints and input/log-score validation retain explicit bounded errors. The native CTC internal extension accepts an aligned byte offset, checks device/range, and invalidates resident generations before validating a new compute attempt. Existing C ABI exports and result layouts are unchanged.

Validation binds the original MPS buffer and offset. Without wildcards, prefix, trellis and backtracking read that same buffer. With wildcards, native Metal reads the borrowed buffer to build the expanded emission, then completes prefix/trellis/backtracking in the second command buffer. No candidate emission host readback or reupload is performed; only token metadata is uploaded and the completed final path plus control flags are read back. Reports separate producer wait, two GPU intervals, native wall time, complete Python bridge time, owned native logical buffers and borrowed offset. Owned-buffer counts exclude the MPS source allocation; physical traffic remains unknown. Constructor compilation is reported separately, and optional warmup covers lazy wildcard setup.

The default direct-input slice reads the final CTC path, then uses original CPU character/word reductions, scaling, rounding and interpolation. Complete aligned JSON, including optional character details, must match the unchanged reference before this trial is considered equivalent. CLI tests include real GPU dispatch and a standalone ASan/UBSan harness for borrowed offsets, invalid ranges, host/borrowed alternation and resident-generation invalidation.

### Optional resident statistics after direct MPS CTC

### Optional nearest interpolation in the MPS context

Add `--mps-nearest-interpolation` with `--ctc-backend native-mps`. Optional `--mps-interpolation-batched` processes subsegment start/end columns in one completion. The wrapper passes one or two packed CPU binary64 columns to the existing native `interpolate_nearest` implementation in the same locked CTC context. Shape bounds are 1..32768 rows per column; GPU kernels compute previous/next valid positions and fill nearest values with previous-on-tie and endpoint filling. Signed zero, infinities and all-missing first-NaN payloads retain the pinned policy. GPU counters distinguish input missing values from actually filled gaps; all-missing columns report zero filled values. One tracked command buffer completes both kernels before returning caller-owned CPU output and counters. Nearest temporaries do not overwrite resident character buffers or invalidate generation/scale, and tests verify statistics remain usable after interpolation.

The existing Pandas 3.0.6/SciPy 1.15.3 Series/frame adapter is reused. It preserves original values until completion, checks paired input/index fingerprints before serving cached results, restores scopes on errors, and handles empty/all-None Series as recorded metadata-only operations. Unsupported methods, dtypes, indices and copy options fail explicitly. Read-only Pandas/NumPy inputs receive an owned writable staging copy before Torch wrapping, reported as `cpu_readonly_input_copy_bytes`; numerical interpolation still occurs on GPU. Pair packing, CPU fingerprints, output Series copies, eight-byte-per-element upload/readback and eight control bytes per column remain. This is shared-context reuse, with an additional interpolation completion, rather than full timestamp residency or fused statistics/interpolation. Add `--mps-retained-interpolation` with resident statistics, nearest interpolation and batching to reuse the completed GPU statistics buffer for paired start/end interpolation. Rebuild the extension to provide `stats_retained` and `nearest_retained`; existing methods and C ABI layouts remain supported. Statistics still return their actual completed numerical values. Compute, scale, replacement statistics and close invalidate previous timestamps.

This mode uploads four-byte source indices instead of eight-byte numerical timestamps. Invalid mappings leave caller output untouched. The paired Pandas adapter keeps per-column fingerprints without building an additional packed numerical input matrix. Statistics readback, CPU provenance snapshots/index mapping, final interpolation readback/Series copies and one additional interpolation completion remain. Standalone word Series keep the copied-input path. Reports distinguish index upload from zero paired timestamp-value upload; they do not claim zero physical traffic, full residency or an additional speedup.
