# Pipeline process traces

`pipeline_trace.py` records a separate CLI Metal System Trace for a source-verified released-dataset case. The original production backend remains unchanged. Required capture options are `--evidence-root`, `--snapshot`, `--catalog`, `--licenses`, `--case-id`, `--source-root`, `--runtime`, `--reference-root` and `--model-specs`. Optional `--quality` defaults to Rapida. Optional `--voices --bridge PRIVATE_EXECUTABLE` captures actual voice phases and turns; speaker references and a private credential bridge are required. Optional timeout is30–1800seconds, default600. The private request is sent through a pipe; credentials never appear in argv, environment or recorded context. Audio, references, rights, source/runtime/model identities and caches are checked before inference, with identity checks repeated after completion.

The controller owns the worker process group, observes its exact PID and attach-ready run ID, then attaches `xctrace` with no prompts. A five-second delay lies outside phase measurements. Structured events must finish without warnings, and the owned child must exit successfully. Timeout or interruption closes pipes and stops owned groups, including descendants after a leader exit. The trace, export XML, controller evidence, spans, source harness archive and review remain private. These diagnostic runs are not benchmark timing replicas.

The reviewer matches the trace target PID to the owned child and synchronized API phases. It credits only Active Compute rows with that exact PID. Foreign process rows and native unattributed `sentinel` rows are counted and excluded. Invalid references, cycles, schemas, missing phase/PID/run identities or failed children are rejected. Generic GPU activity proves work by the selected process; it does not attribute intervals to individual phases or certify each neural operator. All26operator ledger entries remain unverified. This deliberately preserves the stronger operator placement gate.

The capture returns the exclusive review's SHA-256. `--evidence-root ROOT --snapshot SNAPSHOT --verify-sha256 CHECKSUM` verifies the archived review, all retained artifacts, the executed source archive and the recomputed process-level review. This read-only mode needs no model arguments and does not claim that the currently installed runtime or weights are unchanged. Capture source and review source are distinguishable when an existing raw trace is reviewed with a corrected parser.

The recorder gets time to finish saving automatically after the target exits, before a stop signal is considered. Successful worker events are retained before recorder finalization, and a separate capture outcome records both process exit states even when finalization fails. Cleanup targets the owned recorder PID rather than privileged Instruments service descendants.

The controller uses optional `--controlled-start` on the entrypoint: a private line protocol holds inference until the native recorder reports its start, then releases it with `trace_attached`. The native `--notify-tracing-started` barrier uses a dedicated Darwin notification descriptor registered before recorder launch, with token validation and automatic cancellation. The textual startup message is also checked. After the original adapter finishes, the worker stays alive while the recorder saves; only `trace_saved` releases the worker to exit. The entrypoint's default JSON-to-EOF interface remains supported. Recorder startup failure or timeout prevents worker release. A valid archive containing no target GPU intervals remains a missing GPU observation and cannot satisfy the aggregate prerequisite report.

Optional `--max-audio-seconds 1..120` bounds a separate trace to the beginning of a source-verified mono PCM16/16kHz WAV. The source recording is preserved; a new exclusive WAV stores exactly its first frames. Context/review identify the source checksum, derived checksum, frame counts and diagnostic-only scope. This can keep an AMI voice diagnostic within the existing trace-size budget. It does not count as a full-recording trace, an accuracy sample or another benchmark replica. The default continues to use the full source recording.

## Isolated original operations

`isolated_operator.py` uses the same required source/runtime/reference/model/catalog/license options, plus `--operator wav2vec2|alignment_log_softmax|ctc_trellis|ctc_backtrack`, `--case-id` and an exclusive `--snapshot`. It prepares the original alignment checkpoint, an input covering up to eight seconds and an unobserved output reference before the attach-ready signal. The original model must already be in evaluation mode. GPU preparation is drained before attachment; the selected operation runs once, and output readback/hash verification waits until the recorder has saved the trace. Both hashes, shapes and dtypes must match. These warm diagnostics are distinct from cold pipeline benchmark replicas.

The ATen audit forwards each unchanged call and records operation names, tensor device counts and scalar readback counts. It stores no numerical tensor values or credentials. Indexed MPS device names are recognized. CTC uses real checkpoint emissions and up to64valid characters from the published reference solely as a numerical fixture, not as an ASR hypothesis or an accuracy measurement. Original trellis/backtracking remain CPU operations; their evidence is explicitly reported as CPU dispatch.

`--verify-sha256 CHECKSUM --evidence-root ROOT --snapshot NAME` verifies the archived review, artifacts, executed source archive and recomputed review without inference. Historical GPU-only reports are supported only when the archived producer predates the tensor-backend field. The isolated trace can establish GPU work within the selected operation, but the tensor audit alone cannot exclude every numerical CPU path inside a compiled backend. `all_numerical_gpu_verified`, `placement_gate_eligible`, `gpu_placement_certified` and `quality_certified` remain false. The stronger placement gate is preserved.
