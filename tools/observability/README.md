# Transfer diagnostics

`pair.py` runs the unchanged worker and an instrumented worker in separate cold processes, using the existing private caches and licensed released-dataset cases. Capture requires `--evidence-root`, `--snapshot`, `--catalog`, `--licenses`, `--case-id`, `--source-root`, `--runtime`, `--reference-root` and `--model-specs`. Optional `--quality` defaults to Rapida. Optional `--voices --bridge PRIVATE_EXECUTABLE` enables voice diagnostics. Inputs, weights, original source, hardware/runtime identity and the observer source archive are checked; credentials pass only through memory/private stdin after the gates. Run this diagnostic after timing collections, separately from baseline replicas.

The observer forwards unchanged ATen operations and records metadata for `_to_copy`, `copy_` and scalar extraction on the current Python thread. Scoped original API wrappers attribute those calls to phases and restore themselves on exit. Transfers outside these phases remain explicit. Logical source/destination byte counts use tensor size and element size; they are separate because dtype conversions or broadcast copies can differ. CPU scalar accesses are distinct from GPU scalar readbacks. No tensor values, scalar results, pointers, credentials or exception messages enter the audit. Failed dispatches are counted without asserting they were successful copies.

The instrumented result JSON, structured events and all text/SRT/VTT exports must match the original worker without warnings. The exclusive review includes checksums of retained artifacts and the executed observer source archive. `--evidence-root ROOT --snapshot NAME --verify-sha256 CHECKSUM` rechecks that archive, rebuilds the semantic bundles and reconstructs the transfer summary without inference.

This is partial ATen boundary observation. MLX transfers, other threads and copies hidden inside compiled backends remain unobserved. Physical traffic is unknown; tensor views, shared storage and backend implementations prevent inferring it from logical bytes. The audit is a diagnostic run and does not certify benchmark timing, complete transfer coverage or GPU placement. `worker.py --transfer-report NEW_FILE` is an optional wrapper that forwards existing adapter arguments, preserving the original CLI.

Optional `pair.py --python-readbacks` also observes unchanged Python `Tensor.cpu` and `Tensor.numpy` calls on the current thread, through `worker.py --python-readback-report NEW_FILE`. This separate channel covers original API calls even when inference-tensor internals are not exposed through ATen observation. It retains method/device/dtype metadata, logical sizes and same-object CPU returns, restores methods on failure and keeps failed-call counts without messages. NumPy views remain views. The review verifies the additional artifact and includes `python_method_readbacks`; these counters are never added to ATen counters, because the two channels can observe the same copy. Zero ATen readbacks alone cannot establish zero actual readbacks. Compiled calls, other threads, physical traffic and full coverage remain unverified. Existing default reports and archive verification remain supported.
